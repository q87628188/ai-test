# Proposal

## Why

Java/AI 应用方向考核要求基于简历真实项目，交付「接收 → 队列 → 处理 → 结果可追溯」的异步任务方案，并深挖入队不丢失、有界容量/反压、重试与幂等边界。简历中「企业智能问答系统」的文档解析→切片→向量化入库链路天然是 IO/混合型异步任务，最适合作为场景建模与工程落地载体。

## What Changes

- 新建可运行的 Spring Boot（Java 17+）演示工程，建模「文档入库异步任务」场景（任务类型、输入输出、耗时特征、失败概率）。
- 实现自研有界优先队列（基于 JDK 并发原语，不引入 RabbitMQ/Kafka 等中间件），支持优先级与可配置容量。
- 定义「成功接收」持久化边界：任务入队前先落 H2（文件模式），保证进程崩溃后可恢复，满足「进入队列后不丢失」。
- 提供提交/查询/统计 API：快速返回 `taskId`，业务键幂等（同业务键返回同一任务或明确拒绝）。
- 实现 Worker 拉取处理（sleep/本地计算模拟 MinerU/向量化耗时）、失败分类、限次指数退避重试与死信/终态失败。
- 实现优雅停机：停收新任务、内存队列安全回写、线程池限时收敛；重启后从 H2 恢复待处理任务。
- 暴露可观测指标（队列水位、活跃线程、成功/失败/重试、平均排队与处理时延）。
- 补充容量/反压/不丢失权衡文档、单测与并发测试；按提交要求保留 AI 对话与 git 提交历史。

## Capabilities

### New Capabilities

- `task-submission`: 任务提交接收、业务键幂等、`taskId` 快速返回，以及「成功接收」的持久化边界。
- `priority-task-queue`: 自研有界优先内存队列、容量决策依据、超限反压策略。
- `task-execution`: Worker 拉取与模拟处理、失败分类、限次退避重试、死信/失败终态，且重试不无限加压队列。
- `task-observability`: 按 `taskId` 查状态与结果、按状态统计、运行指标暴露，以及优雅停机与重启恢复可追溯。

### Modified Capabilities

- （无）当前仓库尚无既有规格。

## Impact

- 新建 Spring Boot 工程与模块分层（API / application / domain / infrastructure）。
- 依赖：Spring Framework、Spring Data JPA（或 MyBatis）、H2 文件持久化；允许 Guava / commons-lang；禁止队列中间件。
- 数据模型：任务状态表与结果表分离；启动自动建表（DDL 随项目提供）。
- 交付物：可直接启动运行的项目、设计权衡文档、测试、git 历史与 AI 关键对话留存。
